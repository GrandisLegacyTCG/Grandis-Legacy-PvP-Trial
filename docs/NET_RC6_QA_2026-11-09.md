# Grandis Legacy PvP - Network RC6 Stage 1 QA / Release notes
**Date:** 2026-11-09 | **Basis:** RC34 RC5 PvP + S1 networking v3.80.17

## Verified source identities
- VS AI file is **Season 0 RC36, internal RC36.3** (not RC36.0 and not a separately named RC37).
- The last available PvP S0 networking code is **RC34 GitHub RC5**, based on RC34 gameplay.
- S1 PvP baseline for communication is **v3.80.17**; `package-lock.json` pins the same native `ws` release that this S1 archive resolved: `8.21.0`.
- RC36.3 gameplay is **NOT** transplanted in this staging build; otherwise networking changes and donor engine differences would be impossible to isolate.

## Changes in this code
| Area | Before (RC5) | After (NET RC6 Stage 1) |
| --- | --- | --- |
| Production WebSocket | homemade lite adapter | native `ws`, same major library as S1 (offline lite fallback) |
| Initial battle connection | server snapshot + immediate browser resync | one server forceImport snapshot, no redundant browser resync |
| Dev/lite wire handling | JSON encode/decode inside multiple transport adapters | encode and decode only at application edges |
| Slow socket | no bounded snapshot buffer | disconnect/reconnect after >2 MiB buffered |
| Viewer-safe snapshot | recompute on repeat requests in same revision | cache separately for P1, P2 and spectator; no canonical state cache sent |
| Lobby prewarm | none | opportunistic versioned script prefetch after READY |
| Script cache | immediate revalidation | immutable 24-hour cache only for URLs fingerprinted by exact build ID |
| PvP battlefield ping | 25s with no RTT response used | 8s transport ping and displayed smoothed RTT |
| Response visibility | server ACK timing only | record incoming Response render and two animation frames until paint |
| Response / Mana rules | RC5 existing atomic flows | unchanged, regression-tested both seats |

## Tests actually run
- `npm run build:precompress` completed; 73 compressed textual assets; 17.52 MiB raw -> 1.01 MiB Brotli in local estimate. This is transfer encoding, not the full asset/deployment size.
- `npm run check` PASS (full inherited RC34 test matrix plus two new network tests).
- Real RFC6455 WebSocket tests PASS: both seats connected, origin rejection, /health, HTTP fingerprint cache, single connection snapshot, RTT pong.
- Browser-adapter simulation PASS: full initial snapshot only once, no duplicate resync, one packet per Response PASS, exact ACK ownership, Response paint measurement.
- Real RC34 engine and viewer-safe Response scenario PASS in both attack directions (inherited tests). Local/atomic RC5 Mana tests PASS.
- Engine donor and gameplay card data were not changed; no AI behavior removed in this stage.

## Local comparison (10 phase actions per build, single-machine loopback)
| Metric | Original RC5 lite | NET RC6 lite fallback |
| --- | ---: | ---: |
| Median action-to-ACK | 4.88 ms | 4.89 ms |
| Median action-to-opponent-snapshot | 6.61 ms | 6.55 ms |

**Interpretation:** effectively unchanged under loopback; do NOT claim a demonstrated faster experience in Northflank from these measurements. The changes target fewer duplicate transfers at reconnect/start, smoother slow-client handling, native S1 transport, and identifiable bottlenecks. Native `ws` and actual Northflank latency still require CI/hosting tests.

## Limits / not yet certified
- Local environment has no npm registry access, so **native ws dependency and Docker path were not executable here**. GitHub Actions now runs `npm ci` and requires `PVP_REQUIRE_WS=1`, then builds/launches Docker and checks /health `transport=ws`.
- A true live **two-browser/mobile gameplay** sequence, nested Defense/Reaction, network jitter, and full match under hosting have not been completed.
- Start Match still navigates from lobby to `/battle/`, creating a new document/socket; prefetch mitigates loading but **does not solve the one-document S1 architecture gap**.
- RC36.3 engine/UI transfer, removal of AI code/BGM, mobile preview scaling and lobby Hero Card Review are not yet applied.

## Safe field diagnostics
Open `/battle/?pvpPerf=1` (or `/?pvpPerf=1` from lobby) to view the client-side metrics. Record RTT, ACK, import and Response paint times for both clients. Do not include private card details or seat tokens in logs.

## Stage decision
**Suitable for manual push to a GitHub TRIAL/staging branch, not a final production promotion.** Keep one Northflank instance, preserve original RC5 ZIP for rollback, and do not overwrite the main S1 PvP repository.
